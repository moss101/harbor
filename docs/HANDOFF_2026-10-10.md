## 2. Remaining engineering tasks, in dependency order

### T1. Register the Apple OCR + speech adapters in the iOS and macOS runners

**DONE 2026-10-14** (see STATUS follow-up). Verified on screen on the iOS simulator; macOS builds. The design below was followed except: addresses are taken inside the host files (taking them from another file duplicates the C symbols), and no Camera string was added for macOS.
Why: the core exports `harbor_ocr_register_host` / `harbor_asr_register_host` (`core/harbor_ffi/src/lib.rs`),
the Swift adapters exist and are tested via dlopen, but no app registers them, so scans/voice hit the typed
"no OCR/speech engine" error in the shipped app.
Design (decided, not yet built):
- Add `native/apple/ocr_host/OCRHost.swift` and `native/apple/asr_host/ASRHost.swift` to both
  `apps/harbor_app/ios/Runner.xcodeproj` and `macos/Runner.xcodeproj` as `PBXFileReference`s with
  `sourceTree = SOURCE_ROOT` and relative paths (one source of truth; mirror how `AppDelegate.swift` is
  listed at pbxproj lines ~13/51/124/316 (ios) and ~26/69/169/358 (macos); unique 24-hex IDs).
- Guard the speech code: `SpeechTranscriber` needs iOS/macOS 26. Put the implementation behind
  `@available(iOS 26.0, macOS 26.0, *)` and make the `@_cdecl` wrappers return code 1 ("unsupported")
  under `#available` else. The standalone dylib builds with `-target …-macos26.0`; the runners' deployment
  targets are lower.
- Do NOT rely on `dlsym` of the `@_cdecl` symbols (dead-stripping). In `AppDelegate.swift` (iOS) and
  `MainFlutterWindow.swift` (macOS) add a `FlutterMethodChannel("dev.harbor/native_adapters")` method
  `addresses` returning `{ocr:[descriptor,recognize,free], asr:[…]}` as Ints from
  `unsafeBitCast(fn as @convention(c) …, to: Int.self)`.
- Dart: new `lib/services/native_adapters.dart` calls the channel (tolerate `MissingPluginException`);
  pass the map into `HarborCoreWorker.spawn` (`packages/harbor_native/lib/harbor_worker.dart` `_SpawnConfig`)
  and, in the worker right after `harbor_core_open_ex` succeeds, lookup `harbor_ocr_register_host` /
  `harbor_asr_register_host` in the core library and call them with `Pointer.fromAddress(...)`.
  The registry is process-global, so the worker isolate is fine. Log failures via `lastOpenError` text.
- Info.plist strings: `NSSpeechRecognitionUsageDescription`, `NSMicrophoneUsageDescription`,
  `NSCameraUsageDescription` (both platforms); macOS entitlements (`DebugProfile.entitlements`,
  `Release.entitlements`): `com.apple.security.device.audio-input`, `com.apple.security.device.camera`.
  Update `PrivacyInfo.xcprivacy` if required-reason APIs are added.
- Surface it: add an "On-device engines" block to Settings showing `ocr.status` / `speech.status`
  (ops exist) — this is also the verification (screenshot on the simulator).
- iOS DEVICE builds link the static archive; the sim/macOS builds bundle the dylib. Clear DerivedData
  before device builds (stale-core trap, decision 0015).
Verify: iOS sim launch, Settings shows `apple-vision` and (iOS 26 runtime) `apple-speech-transcriber`;
`flutter test` with a fake channel; macOS `flutter build macos`.
